# DK Voiceover — offline translated movie speech

Approved 2026-11-26. Standalone DK Kinehall only. This is a planned major feature inspired by translated-video voiceovers, not an integration with Yandex's proprietary service. First-stage source added; no runtime or model installation yet. Preserve the original Chromium player and all existing settings, audio tracks, subtitle translation and controls.

## Required behavior

- Russian and English translated voiceovers, initially English to Russian and Russian to English; explicit source/target selection plus automatic source-language detection.
- Male/female synthetic voice options and automatic speaker identification/diarization with consistent speaker-to-voice assignment; manual correction and generic voice fallback. Do not assume speaker gender from a voice or promise perfect diarization.
- Generate synchronized spoken translations from the selected original audio track; prefer reliable timed source subtitles when explicitly selected and compatible, otherwise speech recognition. Keep original speech/music/effects available. Background preservation should use genuine separation when available; initially mix translated speech over attenuated original audio, not claim isolated dialogue removal.
- Settings gear: Voiceover On/Off, Original language, Voiceover language, Voice selection (automatic/manual), Original audio level, Voiceover volume, Generate voiceover, status/progress, cancellation, resume from cached results, cache management and optional audio export. Off by default. Never automatically process all library items.
- Ahead-of-playback generation and cached voiceovers so repeated viewing does not require reprocessing. First release may require pre-generation; later bounded lookahead and buffering. No promise of instant dubbing on CPU hardware.
- Seek/pause/resume, playback rate, queue/track changes, loop modes and 200% master volume must stay synchronized. Keep source files unmodified; export only to a separate user-selected output.
- Once explicitly installed, local speech recognition, translation and synthesis must work offline, without subscriptions, paid APIs, online fallbacks or transmission of files, transcripts or generated voices.

## Proposed components (candidates, not yet pinned or redistributed)

- [whisper.cpp](https://github.com/ggml-org/whisper.cpp): local speech recognition and timestamped segments; select CPU-capable multilingual model.
- [OPUS-MT](https://github.com/Helsinki-NLP/Opus-MT), CTranslate2 and SentencePiece: reuse the existing English/Russian subtitle translation runtime where compatible, translate in context-aware bounded batches.
- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx): evaluate local text-to-speech and speaker diarization models; verify usable English and Russian voices, speaker assignment, phonemization and CPU performance.
- Existing FFmpeg/FFprobe: extract selected audio, resample, inspect timing, mix and export. Evaluate actual dialogue/background separation model separately if needed.

## Implementation sequence

1. Review and pin each upstream engine, individual model/voice license, redistribution terms, notices, dependencies and checksums. Design opt-in runtime provisioning, no surprise downloads, disk/RAM budget and a CPU mode suitable for Surface Pro.
2. Secure native job manager: validate selected-file identity and track, restrict IPC, process arguments and cache roots, bound duration/input/output/CPU and memory, progress by stage, cancel workers and clean partial artifacts, never execute arbitrary shell commands or download implicitly.
3. Timestamped ASR and language detection; source subtitle import; segmentation, speaker diarization and stable speaker assignment. Preserve silence and original media timeline, including nonzero origins and variable frame rates.
4. Offline translation with existing local bilingual models; sentence context, punctuation and timing-aware segmentation; maintain originals and expose errors without fabricating translations.
5. Synthesize generic English/Russian voices, align durations using bounded tempo adjustment or sensible resegmentation; avoid truncated dialogue, long drift and overlapping speech.
6. Generate synchronized audio in bounded chunks, original-audio ducking/mix and independent gain controls; use real separation only when supported. Do not imply original music/effects are isolated if the original track is merely attenuated.
7. Cache keyed by verified file identity, audio-track identity, model/voice versions, languages and synthesis options; atomic manifests, size quota, invalidation, explicit clear and deletion behavior. No duplicate media videos or sharing transcripts.
8. Integrate player clock, seek, pause, playback-rate, loop and queue transitions. Select cached voiceovers, fallback to original audio if absent or failed; preserve subtitle and existing audio controls.
9. Export generated audio as a separate file, optionally mixed or standalone translated track; preserve originals. Add ahead-of-playback generation and optional background preservation only after basic synchronization is accepted.
10. Acceptance: actual English/Russian movie clips, male/female voice options, multiple speakers, noisy music, silence, long movies, seeking, track switching, native transcode/direct playback, cancellation, cache reuse, exports, offline operation, licenses, and Surface Pro CPU/RAM/disk use. No source commit alone establishes dubbing quality or runtime availability.

See [master roadmap](ROADMAP.md), [subtitle translation](SUBTITLE_TRANSLATION_ROADMAP.md), and [codec packaging](CODEC_PACKAGING.md). Current work remains source-only; no compile, tests, model downloads or terminal commands unless authorized.

## First-stage implementation status (2026-11-26)

The new standalone Voiceover settings category starts an explicitly requested local job using the selected original text subtitle track and English/Russian translation direction. It reuses the local translation runtime and expects separately provisioned compatible sherpa-onnx Python modules and single-speaker VITS voice assets under translation-runtime/voices/en and /ru (READY.json, model.onnx, tokens.txt and espeak-ng-data). No installer, audited model selection, dependency locking or verified speech runtime is supplied in this build. Native job limits are 6000 cues, three hours of cue timeline, two CPU threads and bounded output, with stage progress, cancellation, temporary-file cleanup and exclusive new-file WAV export. Speech is fitted to available cue intervals with bounded speed adjustment; lines that cannot fit are skipped and flagged rather than cut off. This is separate audio generation/export, not live translated movie playback. Original audio, movie files and subtitles are unchanged. ASR, diarization, voice selection, native seeking integration, persistent cache, mixing and full acceptance are still outstanding.

## Second-stage source: synchronized speech playback

The standalone Voiceover category now offers Enable voiceover, Original audio level (default 35%) and Voiceover volume (default 100%), plus the existing generation and export actions. Explicitly enabling a completed generated track obtains a random, session-scoped loopback WAV URL with byte-range support; no full audio file is transferred through IPC. The same video remains playing. The separate audio follows the source playback clock, seeks, pause/resume, buffering and speed, with drift correction and the existing master gain/mute. Original volume is reduced only while generated speech playback is active; error, end, stop or switching media restores the original level. Temporary results are revoked and cleaned on discard, with in-progress export protected. This is pre-generated subtitle-based dubbing, not instant ASR or dialogue separation; silence in the generated track still uses the selected original level while active. Runtime/voice assets remain uninstalled and unverified. Verify direct/native playback, audio gain, seek drift, buffering, repeat, switching, offline behavior and actual voices before acceptance. Arabic, ASR, multiple voices and persistent cache remain roadmap items.

## Offline speech recognition first

Source now supports local audio extraction and timestamped Whisper.cpp SRT generation before voice synthesis if no compatible original subtitle track is selected. An explicit Generate subtitles from audio action can work independently of voice models; generated transcripts can be displayed and exported. Cache keys include source path/stat, audio ordinal, source language and runtime/model file stats; bounded private SRT cache, temporary mono PCM cleanup and cancellation. Candidate runtime contract: XDG data dk-kinehall/speech-runtime/bin/whisper-cli, models/ggml-base.bin and READY.json, plus packaged FFmpeg/FFprobe. CPU two threads, maximum three-hour source, explicit English/Russian direction. Model and CLI are not installed, pinned or verified; no installer yet. Verify extraction timestamps, actual audio stream selection, subtitle display/delay, native seeking, cache eviction and accuracy. Arabic, auto language detection, diarization and persistent generated audio cache remain planned. Prefer local ASR over online subtitle accounts.

## Persistent generated audio reuse

The standalone native Voiceover worker now reuses a local WAV when the requested timed cues, direction, worker version and model/voice/runtime file-stat inventory match a previous explicit generation. The generated WAV format and expected cue duration are checked before reuse; playback receives a new session token and hard link, so ordinary eviction cannot invalidate an active stream or export. Completed cache entries are bounded to eight and 1 GiB under normal successful pruning; errors fall back to generation. Generated audio is retained locally after playback, not uploaded. This first cache does not bind to the source media path (identical cues can safely share synthesized output), does not hash all runtime dependency bytes, and still requires explicit cache clearing/management and recovery of crash-left temporary folders. No setup, compilation, transcription or synthesis verification occurred. Next source work: cache management and speech-language detection, then Arabic ASR/translation/TTS direction support subject to models and licensing.

## Cache management source

The existing standalone Voiceover settings now expose completed-cache soundtrack count, size in MiB, and an explicit native-confirmed Clear voiceover cache action. Generation/export are protected against clearing; active audio remains available through its session hard link. No original video, exported WAV, generated subtitles, models or playback history is removed. Single-instance startup attempts cleanup of recognized stale session/staging directories using only expected file names. Unknown/damaged entries and temporary files outside the cache root may remain; size reports completed WAV files only, not total filesystem allocation. Verify installed UI in both languages, clear during playback, quota and crash recovery. No runtime setup or testing in this source build.

## Automatic spoken-language detection source

Standalone Voiceover offers an optional automatic English/Russian direction. It runs the pinned multilingual Whisper CLI in automatic language mode on the selected audio track, reads the CLI's detected-language log and accepts only English/Russian with reported probability at least 0.5. The actual recognized language labels the SRT and selects the opposite translation direction, subject to installed translation/voice availability. Automatic transcripts use separate language-suffixed cache names; manual transcripts cannot masquerade as detected results. Manual directions remain available. The first detection is global to the clip, not continuous or speaker-specific, and opening silence/music may cause failure; 0.5 is a provisional acceptance heuristic, not a calibrated confidence guarantee. Other languages are not yet accepted. No runtime, setup or testing performed.

## Arabic and optional voices source

Arabic (`ar`, `ara`) is now accepted by the multilingual ASR pipeline, including automatic detection. Standalone subtitle translation and Voiceover accept six direct pair directories (`en-ru`, `ru-en`, `en-ar`, `ar-en`, `ru-ar`, `ar-ru`); missing models remain disabled through readiness checks. Auto source can select a target explicitly; the previous automatic option maps English to Russian and Russian/Arabic to English. Matching source/target is not translated. Generated Arabic text keeps its actual language and uses Chromium WebVTT Unicode rendering; RTL and mixed bilingual cues must be checked on Linux. Voiceover accepts a fixed `default`, `male` or `female` profile, each requiring matching model/phonemization assets under `translation-runtime/voices/<target>` for default or `.../<target>/<profile>` for optional variants. Cache keys incorporate the actual selected model files. These choices are whole-track profiles, not inferred speaker characteristics. No models or binaries added, no downloads or runtime tests. Suitable Arabic direct translation and TTS models and licenses must still be independently selected and validated.

## Speaker-aware synthesis source

Optional standalone speaker mode uses the sherpa-onnx offline diarization API with explicitly provisioned `translation-runtime/diarization/{READY.json,segmentation.onnx,embedding.onnx}` and the existing Python runtime. Audio is extracted from the selected native source, rebased and processed locally, with cancellation, progress, a 60-minute limit and at most 32 anonymous speaker clusters. Voiceover assigns each timed cue to its greatest-overlap speaker when unambiguous; otherwise it uses the default voice. Initial alternating male/female voice profiles are simply distinct voices, not gender classification, and the user can override each speaker's assignment. Speaker mode requires all three target-language voice profiles; the worker lazily loads requested voices, converts supported sample rates to one WAV rate and retains the original timing limits. Cache identity includes per-cue assignments and model inventory. This is experimental source, not verified diarization or long-film support. Model selection, redistribution, actual quality/performance and persistent speaker mapping remain outstanding.

## Progressive synthesis playback source

The optional standalone setting Play generated audio while synthesis continues publishes complete 30-second PCM WAV chunks (last may be shorter) from the synthesis worker using atomic file renames. A random session token and validated chunk index restrict loopback playback; only completed chunks are served. The player can enable voiceover once a chunk exists, maps source playback time to its chunk offset, restores original audio when a section is unavailable, and switches to the completed full WAV after generation. Export and persistent cache still require successful full synthesis. ASR and translation are currently completed first, and synthesis runs in timeline order from zero; this is progressive synthesis, not streaming ASR or seek-prioritized lookahead. No guarantee of real-time throughput or gapless chunk transitions. Temporary full WAV plus chunks can occupy about twice the generated audio size until discard; startup cleanup includes recognizable chunk names. No runtime or model installation or acceptance testing. Validate cache hits, cancellation, seek/rate/pause, boundary gaps, memory/disk use and failures; pursue playhead-prioritized production and separation next.

## Playhead-prioritized generation and speech-sensitive mixing

Source now generates independent 30-second segments in playhead-priority order, with current/forward lookahead, live priority changes on seek or segment crossing, incremental translation and synthesis, and one synthesis per cue even when it spans segment boundaries. A sparse fixed-duration PCM WAV allows out-of-order assembly; each segment is published only after all overlapping cue dependencies are complete. Full cache and export remain completion-only; the worker version changes cache identity. A seek takes effect after the current segment finishes, not during an active synthesis call. ASR without source subtitles still needs a complete recognized transcript first. Progress represents processed cues, not guaranteed completion of all silent segments. The same speech worker time and cue-duration bounds remain.

Speech-sensitive ducking defaults on, using generated audio RMS and a short hold to restore original audio during quiet intervals; continuous attenuation remains available. Optional stereo center reduction uses a Web Audio mid/side matrix while translated speech is active, retaining the side signal while reducing the centered signal according to the original-audio slider. It is off by default, downmixes only the processed path to stereo, and falls back to ordinary attenuation for the separate MKV audio path or unavailable matrix. Centered music/effects may also be attenuated, off-center voices may remain, and mono content may not benefit. This is NOT genuine source separation, and no separation model is installed or selected. Actual source separation, long-film speaker tracking, runtime/model provisioning and installed playback validation remain open. Verify real cue boundaries, seek reprioritization, silence, master volume, audio routing, clipping and cancellation before accepting. No runtime tests or downloads performed.
